# Verrail 专业交付流程

版本：0.1

状态：`Confirmed`

最后更新：2026-08-25

## 1. 目的

Verrail 的产品与工程工作使用同一套可审阅交付流程。流程的目标是尽快形成正确的产品闭环，同时让范围、责任、证据、验收和回滚保持明确。流程不要求所有改动采用相同治理强度，也不把文档数量当作交付质量。

## 2. 三种交付模式

| 模式 | 适用范围 | 必要产物 | 默认验证 |
| --- | --- | --- | --- |
| `Light Execute` | 局部修复、低风险样式、内部重构 | 目标、改动、测试结果 | 最小相关测试 |
| `Audit And Batch` | i18n、文案、帮助内容、批量一致性修正 | 覆盖审计、批次边界、代表性验证、残余风险 | 词条一致性、类型检查、关键旅程抽查 |
| `Governed Delivery` | 产品语义、数据、权限、运行、删除、发布与 AI 自治 | 产品契约、影响分析、工作图、证据、验收与回滚 | 纵向合同测试和完整交付门禁 |

风险升级采用就高原则。文本改动一旦影响权限、审批、删除、外部动作或数据解释，即进入 `Governed Delivery`。

## 3. 标准流程

### Gate 1：Outcome

明确用户结果、责任人、成功指标、非目标和时间边界。没有可观察结果的需求不能进入实施。

### Gate 2：Product Contract

确定产品行为、对象语义、用户旅程和兼容边界。影响 Verrail 核心对象的内容写入 `product-design.md` 或 `operational-ontology.md`；单项持久技术决策写入 ADR。

### Gate 3：Impact Inventory

盘点 UI、API、数据、权限、运行时、文档、迁移和测试影响。删除功能必须同时盘点入口、路由、服务、数据表、后台任务、依赖、配置和存量数据。

### Gate 4：Delivery Graph

把工作组织成可独立验收的纵向切片。每个切片声明输入、输出、依赖、完成定义、验证方法和回滚方式。大范围文本工作按用户工作流批处理，不按单个字符串拆任务。

### Gate 5：Readiness Review

实施开始前确认：

- 产品契约和范围已由责任人确认；
- 不可逆决策、迁移和删除风险已有处理方案；
- 测试环境、代表性数据和验收人可用；
- 未决问题不会迫使实现者猜测产品语义。

### Gate 6：Execute

按纵向切片实施，每个切片保持可运行。兼容迁移优先采用“新路径可用、旧路径冻结、调用量归零、再删除”，避免长期双写和一次性大爆炸替换。

### Gate 7：Evidence Review

提交可复现证据，包括测试命令、关键结果、截图或可检查产物、数据对账和已知风险。作者自述不能替代自动检查或独立评审。

### Gate 8：Acceptance And Release

Outcome Owner 对固定版本完成验收。发布前确认迁移、回滚、运维和观测；发布后验证真实用户旅程，并把未完成项重新进入 Outcome，而不是静默留在代码中。

## 4. 状态模型

```text
Draft
  -> Ready_For_User_Review
  -> Confirmed
  -> In_Progress
  -> Evidence_Ready
  -> Accepted
  -> Released
```

`Blocked` 和 `Rejected` 是带原因的旁路状态。产品契约处于 `Ready_For_User_Review` 时可以继续调查和原型验证，但不能开始不可逆的数据迁移、功能删除或正式实现。

## 5. Definition Of Ready

工作进入 `In_Progress` 前必须满足：

1. 用户结果与非目标明确；
2. 产品责任人、实施责任人和验收责任人明确；
3. 影响范围和兼容策略已盘点；
4. 每个切片有完成定义和验证方式；
5. 高风险动作有审批、迁移与回滚路径；
6. 当前 SSOT 已反映确定的产品语义。

## 6. Definition Of Done

工作进入 `Accepted` 前必须满足：

1. 关键用户旅程达到验收条件；
2. 数据、共享合同、服务、UI 与文档保持一致；
3. 最小相关测试通过，广泛改动通过类型检查、测试和构建；
4. 错误、空状态、加载、取消和恢复路径可用；
5. 兼容、迁移、隐私、安全和运维风险已说明；
6. 证据绑定到可识别的提交或构建版本。

## 7. P0 应用

P0 使用 `Audit And Batch` 锁定用户可达表面，并按用户工作流实施中文 i18n。当前业务功能保持不变，内部设计、测试和开发页面不进入翻译范围。生产内部路由的清理由独立 `Governed Delivery` 任务处理，不作为 i18n 门禁。具体计划见 [`p0-plan.md`](./p0-plan.md)。
